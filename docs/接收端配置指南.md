# AEBS 遙測接收端配置指南（上車版）

> 給接收端電腦 agent 的完整操作文件。

## 系統資料總覽

發射端每 **500ms** 無線回傳一包，包含以下資料：

### 遙測欄位（共 16 項）

| 類別 | 欄位 | 單位 | 說明 |
|------|------|------|------|
| 溫度 | motor_a_temp ~ motor_d_temp | °C | 馬達 A~D 溫度 ×4 |
| 溫度 | ctrl_a_temp ~ ctrl_d_temp | °C | 控制器 A~D 溫度 ×4 |
| 電池 | bat_soc | % | 電池 SOC |
| 加速度 | acc_x / acc_y / acc_z | g | 三軸加速度（CH110） |
| 電壓 | bat_voltage | V | 電池總電壓 |
| 電壓 | bus_voltage | V | 電機母線電壓 |
| 車速 | motor_speed | rpm | 電機轉速（代替車速） |
| 通訊測試 | test_counter | — | 每包遞增（0→255 循環），驗證鏈路 |

加上協定元數據（序號、時間戳），共 **18 項**。

> 欄位值由 CAN 總線提供；若某幀尚未收到，該欄位為空（WebUI 顯示 `--`）。`test_counter` 則永遠遞增。

- 無線串口參數：**9600 8N1，無校驗**
- 協定：TLV + CRC16，幀頭 `0xA5 0x5A`

## 三、硬體接線（AS32-TTL-100 模組 + USB-TTL）

| USB-TTL | AS32 模組 | 說明 |
|---------|-----------|------|
| GND | GND | 共地 |
| TXD | RXD | 電腦發→模組收 |
| RXD | TXD | 模組發→電腦收 |
| 3.3V | VCC | **用 3.3V，勿用 5V** |
| — | M0 → GND | 低電平（透傳） |
| — | M1 → GND | 低電平（透傳） |

- M0、M1 各用杜邦線短接到 GND（= M0=0、M1=0 透傳模式）
- AUX 不接；**天線必須接上**（不接天線會大量丟包，且可能燒毀功放）

## 四、確定 COM 口

```powershell
Get-PnpDevice -Class Ports | Where-Object {$_.FriendlyName -match 'COM'} | Select-Object FriendlyName
```

記下接收端 USB-TTL 的 COM 口（如 COM3）。

## 五、啟動 WebUI

```powershell
cd <專案目錄>
python tools\webui_server.py --port COM3 --baud 9600 --web 8080
```

看到 `[webui] 瀏覽器開啟: http://localhost:8080` 即成功。

## 六、瀏覽器檢視

本機瀏覽器開啟：**http://localhost:8080**

頁面區塊（由上到下）：
1. **頂部**：測試計數（通訊指示）、序號、封包數、更新時間
2. **加速度**：X / Y / Z 軸（g）
3. **車況**：電機轉速（rpm）、母線電壓（V）、電池電壓（V）
4. **溫度**：馬達 A~D、控制器 A~D（°C）
5. **電池**：SOC（%）

## 七、驗證標準

- [ ] 連線狀態燈為綠色
- [ ] 頂部「測試」數字每 500ms 遞增（通訊成功）
- [ ] 封包計數約每秒 +2
- [ ] 上車後溫度/電壓/轉速/加速度/SOC 陸續有值、持續更新
- [ ] 某幀尚未收到時該欄位顯示 `--`（正常）

## 八、疑難排查

| 症狀 | 原因 | 處理 |
|------|------|------|
| 完全無輸出、連線燈灰 | COM 口錯 / 驅動 / 接線 | 查 COM 口、核對 TXD/RXD 交叉 |
| 連線燈綠但「測試」不變 | 模組參數不一致 | 進配置模式（M1=3.3V）對齊頻道/地址/空中速率 |
| 「測試」跳號 | 無線丟包 | 接天線、縮短距離 |
| 所有 CAN 欄位全 `--` | CAN 未接/ID 不符 | 確認板子 CAN 已接車上總線、`CAN_USE_LOOPBACK=0` |
